= Configuration Providers

include::./includes/attributes.adoc[]

This extension includes two built-in providers that read flag values from Quarkus configuration.
These are useful for development, testing, or simple deployments where flags are known at build time or runtime.
For production use with dynamic flag evaluation, consider a dedicated provider such as flagd or Unleash.

== Runtime configuration provider

The runtime configuration provider reads flag values from Quarkus runtime configuration.
Values can be overridden at deploy time using environment variables, system properties, or external config files, as described in https://quarkus.io/guides/config-reference[Quarkus Configuration documentation].

Add the dependency:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>io.quarkiverse.openfeature</groupId>
    <artifactId>quarkus-openfeature-runtime-config</artifactId>
    <version>{project-version}</version>
</dependency>
----

Define flags in `application.properties`:

[source,properties]
----
quarkus.openfeature.runtime.new-feature=true
quarkus.openfeature.runtime.greeting=hello
quarkus.openfeature.runtime.max-retries=3
quarkus.openfeature.runtime.max-bytes=10000000000
quarkus.openfeature.runtime.threshold=0.75
----

Values are written as strings, so the type of a flag is inferred from its value.
The narrowest type that holds the value exactly wins: `true` and `false` are booleans, a whole number is an integer or, if it doesn't fit, a long, and any other number is a double.
A JSON object or array is a structure, and everything else is a string.

Structured flags are therefore written as JSON:

[source,properties]
----
quarkus.openfeature.runtime.limits={"max":10,"enabled":true}
quarkus.openfeature.runtime.regions=["eu","us"]
----

A flag can be evaluated as a type other than the inferred one:

Boolean evaluation:: Never fails. A value that is not a boolean is false, so note that only `true` is truthy (case insensitive), all other values are false.
Integer, long and double evaluation:: Throw an error unless the flag is a number of that type. A long or a fractional value is not truncated to an integer; a whole number is a valid long and a valid double.
String evaluation:: Never fails. A flag of any other type is rendered in its canonical form, which is not always the text that was configured: `3.10` reads back as `3.1`, and the whitespace in a JSON value is not preserved.
Object evaluation:: Never fails. A flag of any other type is returned as a value of that type.

For named domains, flags are scoped under the domain name:

[source,properties]
----
quarkus.openfeature."experimentation".runtime.experiment-a=true
quarkus.openfeature."experimentation".runtime.experiment-b=false
----

== Build-time configuration provider

The build-time configuration provider reads flag values that are fixed at build time.
These values are baked into the application and cannot be changed at runtime, even with environment variables or system properties.

Add the dependency:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>io.quarkiverse.openfeature</groupId>
    <artifactId>quarkus-openfeature-buildtime-config</artifactId>
    <version>{project-version}</version>
</dependency>
----

Define flags in `application.properties`:

[source,properties]
----
quarkus.openfeature.buildtime.stable-feature=true
quarkus.openfeature.buildtime.api-version=v2
----

For named domains:

[source,properties]
----
quarkus.openfeature."experimentation".buildtime.locked-flag=false
----

== Using both providers

You can use both providers together.
Add both dependencies and configure the provider order:

[source,properties]
----
quarkus.openfeature.provider=runtime-config,buildtime-config
----

The first provider in the list that has a value for a given flag wins.
In this example, runtime flags take precedence over build-time flags.

This can be useful to define build-time defaults that are overridable at runtime:

[source,properties]
----
quarkus.openfeature.provider=runtime-config,buildtime-config

# Build-time default
quarkus.openfeature.buildtime.new-feature=false

# Runtime override (e.g., set via environment variable in production)
quarkus.openfeature.runtime.new-feature=true
----
